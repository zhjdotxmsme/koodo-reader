Android 原生手势桥接（路线 2 + 原生选择菜单）

Spec · 2026-09-17 · 项目 koodo-reader · 状态：设计已批准，待实现
看板任务: 本 spec 批准后创建 上游事实: 官方 APK 闭源 RN 壳, 主仓库无 Android 构建
一句话目标：把 APK 从"能用的网页壳"升级为"官方级原生壳体验"——引擎 22 种桥事件全部消费， 选择菜单/图片/链接/翻页走原生路径，引擎移动端模式（isMobile:"yes"）启用， 所有协议常量收敛到一个可单测的纯 CJS 模块。

目录

1. 背景与事实依据 2. 架构 3. 协议 4. React 侧 5. Kotlin 侧 6. 测试 7. 风险与回退 8. 验收标准

1. 背景与事实依据

  • 主仓库无任何 Android 构建：release-appx.yml = Windows 商店包，release.yml = 桌面端；org 无 Android 仓库；package.json 无 Capacitor。
  • 引擎 kookit.min.js 含 38 处 无防护的 window.ReactNativeWebView.postMessage(...) 调用，发出 20 种事件 —— 官方安卓壳即此消费者（React Native WebView），壳内跑的仍是同一 web 构建。
  • 当前 APK 的 AndroidBridge.postMessage 只处理 error（Toast），其余事件全部丢弃；isMobile 在 3 处硬编码 "no"。
  • App 侧已有可复用钩子（本次调查发现）：
    • viewer/component.tsx → live htmlBook.rendition 上的 next()/prev()（TTS 在用的真实翻页 API，textToSpeech/component.tsx:552）；handleLeaveReader 是面板开关不是翻页（已勘误）
    • PopupMenu（app shell 层，持有 live rendition，负责高亮/笔记/复制/搜索）
    • ImageViewer（app shell 图片查看器）
  • 用户已确认：走路线 2（原生为主），选择菜单替换为原生菜单，设计已批准。

2. 架构

书内 iframe (引擎 kookit)
  → window.ReactNativeWebView.postMessage(事件)  [shim 注入, 现状已有]
  → AndroidBridge.postMessage(json)  [Kotlin]
  → NativeEventDispatcher  [新增]
    ├─ a) 纯原生: 选择菜单/剪贴板/分享/ACTION_WEB_SEARCH/系统浏览器/脚注弹窗/图片查看
    └─ b) 回注 JS: webView.evaluateJavascript("window.__koodoNative.<fn>(args)")
            · nextPage()/prevPage() → live rendition.next()/prev()
            · showSelectionMenu(payload) → app PopupMenu 的高亮/笔记动作（复用引擎调用）
            · menuLabels(labels) → JS 下发 i18n 文案到原生菜单
为什么回注 JS 不算违背"原生为主"：引擎的高亮/笔记能力只能经由 live rendition 对象调用， 该对象只存在于 app 内（viewer/component.tsx:283）。原生侧重写 = 重实现引擎 API，风险不可控。 官方 RN 壳必然采用等价手段（JS 回注或私有 API）。__koodoNative 是显式契约，函数名与参数在本 spec 定死。

3. 协议（唯一事实源：src/utils/android/nativeBridge.js

纯 CJS，.d.ts，Jest 覆盖。延续 folderBridge.js 模式（react-scripts roots=src 可导入）。 Kotlin 侧手写同形常量（Kotlin 无法 import JS），用注释互相标注，CI 编译为唯一 Kotlin 门。

事件名常量（引擎 → 壳，来自 kookit.min.js 实测）

事件关键字段处置（Kotlin）
swipe （非 sliding 模式的翻页请求，方向含在事件语义） 无按事件上下文回注 nextPage()/prevPage()；事件无方向字段时默认下一页（引擎对左右滑分别发 left/right）
scroll-top / scroll-bottom无prevPage() / nextPage()
left / right无prevPage()（right tap = 下一页? 以引擎语义为准：right=prev? 实现时以引擎源码 Ti("left"|"right") 分支语义对齐）
select-textselectedText, sentence, position, range存 payload → 原生浮动菜单（见 5.1）
select-text-after-touch同 select-text同上
selection-change—关闭已开的原生菜单
view-imageimgSrc（data: URI）原生全屏 Dialog（内嵌 WebView 渲染，免费 pinch zoom）；>15MB 回退 Toast 提示用网页版查看
link-clickedhref, footnoteexternal → ACTION_VIEW；有 footnote 内容 → 原生脚注 Dialog；两者皆无 → Toast
pinch-zoomchapterDocIndex, scale引擎自行重渲染（handleRenderPDFChapter），壳仅记录（logcat），不处理
user-agent—固定处置：logcat 记录并忽略（引擎仅请求壳 UA 用于环境判断，无反馈通道；若后续实测发现引擎依赖回传，再经 __koodoNative 扩展）
book-inited / content-loaded / metadata / page-changed / chapter-pages / scroll-text / cache / finish-download / get-ocr-result / error —仅 error 保留现有 Toast；其余 logcat 记录（观测点，为后续扩展留口）

回注函数（壳 → app，宿主=PopupMenu 组件，window.__koodoNative）

函数参数行为（React 侧）
prevPage() / nextPage()—调用 live rendition.prev()/next()（TTS 在用的真实翻页 API；勘误：最初误写 handleLeaveReader=面板开关）
openSelectionMenu()—调用 PopupMenu 的 openMenu()（app 自己的选择菜单：高亮/笔记/翻译/朗读全可用，选区由引擎保持）。原生菜单的"高亮"与"笔记"两项都委托它——不重写高亮逻辑（刻意取舍）
（下发）AndroidBridge.setMenuLabels(json){copy,highlight,note,share,search} 的 i18n 文案PopupMenu 挂载时推送；Kotlin 端缓存用于原生菜单，缺失回退英文硬编码

注意：引擎在 view-image 中已把 blob: 转 data: URI（Li(t).then(...)），Kotlin 无需碰 blob。

5. Kotlin 侧改动

5.1 新增类 NativeEventDispatcher.kt

  • dispatch(json: String)：解析 event 字段分派（协议名与 nativeBridge.js 对齐，注释互引）。
  • 选择菜单：PopupWindow（不用 ActionMode——不需要 ActionBar 语义）锚定在 position 屏幕坐标附近，自动 clamp 到屏内；项序固定：复制 / 高亮 / 笔记 / 分享 / 搜索；文案取 JS 下发的 labels（缺省回退英文硬编码）。点击后关闭。
  • 原生能力：ClipboardManager、ACTION_SEND(text/plain)、ACTION_WEB_SEARCH、ACTION_VIEW(https)。
  • 回注：webView.evaluateJavascript("window.__koodoNative && window.__koodoNative.${fn}(${quoted})")，payload 经 org.json 序列化（延续 folderBridge 的"JSON 字符串"交付风格）。

5.2 ImageViewerDialog（新文件）

  • 全屏透明 Dialog，内部一个只读 WebView 加载 imgSrc（data: URI，pinch zoom 由 WebView 免费提供）。
  • 尺寸阈值：payload >15MB 不渲染，Toast 提示；解码失败同样回退。
  • link-clicked：footnote 非空 → 文本 Dialog（等宽滚动、复制按钮）；external → 系统浏览器。

5.3 MainActivity.kt 改动

postMessage现有 error Toast 保留；其余事件全部转发 dispatcher.dispatch(rawJson)（原"仅 error"分支删除）
shimpostMessage 转发不变（已验证）；新增 setMenuLabels(json) 注入方法供 app 下发文案
WebView 配置追加 settings.useWideViewPort = true、loadWithOverviewMode = true（消除任何"桌面宽屏"渲染风险）；其余不动

7. 风险与回退

风险缓解
left/right 翻页方向语义与引擎实际相反实现时以 kookit.min.js 中 Ti("left"/"right") 调用上下文核对；方向错误=单行翻转，代价低
原生菜单与 app 残留弹窗双弹R5 抑制 + selection-change 关菜单双保险；真机抽查列入验收
大图 data URI 撑爆内存15MB 阈值 + 异常捕获回退
PopupWindow 在沉浸态下定位偏移clamp + 真机抽查；不行则退化为屏幕顶部 ActionMode
Kotlin 改动面扩大 → CI 编译风险新增代码集中在 2 个新文件；MainActivity 为小改；编译错误仍走既有 CI 诊断流

8. 验收标准（DoD）

  • ✓ isMobile 在原生壳内为 "yes"（3 处注入点，harness 断言）
  • ✓ 20 种事件全部有显式处置或显式记录（无"静默丢弃"分支残留）
  • ✓ 长按选词出现原生菜单，五件套可用，文案跟随 app 语言
  • ✓ 翻页手势（swipe/scroll-top/bottom）驱动 handleLeaveReader
  • ✓ view-image 原生查看；link-clicked 浏览器/脚注分流
  • ✓ Jest 全绿（59 既有 + 新增）、tsc 绿、CI 编译绿、APK 重打包产出
协议常量表与 folderBridge.js 同风格：名字、形状、默认值都在一处定义；Kotlin 侧以注释引用行号保持同步。
