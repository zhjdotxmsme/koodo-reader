设计规格：安卓壳移动模式（mobile-mode）

日期：2026-09-18 状态：待用户审阅 路线：壳 + WebView（路线 2） 方案：A（壳感知移动模式）

1背景与根因

用户在安卓真机反馈：APP 打开后呈现宽屏桌面式排版，没有走移动端样式。排查结论：

证据链（均已核实）
  • 打包进 APK 的 webapp/index.html 含正确 viewport：width=device-width,initial-scale=1；MainActivity 设 useWideViewPort=true + loadWithOverviewMode=true —— 视口配置正常。
  • 用户确认书库页「从本地导入 / 从云端导入」按钮出现在屏幕左下角 —— 即 header.css 的 @media (max-width: 950px) 断点已生效，WebView 确实在按手机宽度排版。
  • 全项目移动端响应式 CSS 仅有 4 处：header.css（≤950px 导入按钮移至左下）、sidebar.css（≤950px 侧栏高度微调）、popupMenu.css（≤576px）、stats.css（≤900px）。没有底栏、移动菜单、抽屉等移动导航模式。

根因定性：web 应用是桌面优先设计，移动适配层近乎空白。官方 APK 的"手机应用观感"来自 React Native 原生重写的书库/菜单 UI，与其 WebView 渲染层无关；本项目走路线 2（壳 + 完整 web 应用），必须靠 web 层自身的移动布局改造解决。

2目标与非目标

目标

  • 窄屏（<700px）下书库页呈现真正的移动布局：紧凑顶栏、抽屉侧栏、大封面网格、触控友好。
  • 对话框在窄屏近全屏呈现，触屏可正常操作。
  • 桌面端（≥700px）渲染零变化（结构性保证，见 §3）。
  • 屏蔽 Android 系统字体缩放对 WebView 布局的破坏。

非目标（范围控制）

  • 阅读页面板（目录/设置）全屏化 → 二期；一期只保证窄屏不出血（面板本就按 100% 弹性布局）。
  • 底部 tab 栏、手势导航、safe-area 避让 → 二期按真机反馈再定。
  • 不引入 React Native 式独立移动组件树（方案 C 已否决）；不新增 Redux 状态、不加持久化；不触碰阅读引擎与 IPC。

3核心决策：单一门控根类

决策移动样式不使用媒体查询，统一挂在根类 body.mobile-mode 下；该类由 JS 挂载：

// 纯函数，可单测
export function isMobileViewport(width: number): boolean {
  return width < 700;
}

// App.tsx 挂载 + resize 重算（rAF 节流）
useEffect(() => {
  const apply = () =>
    document.body.classList.toggle("mobile-mode", isMobileViewport(window.innerWidth));
  apply();
  let raf = 0;
  const onResize = () => { cancelAnimationFrame(raf); raf = requestAnimationFrame(apply); };
  window.addEventListener("resize", onResize);
  return () => { window.removeEventListener("resize", onResize); cancelAnimationFrame(raf); };
}, []);

理由：

  • 单一判定源，杜绝"CSS 媒体查询说移动、JS 行为说桌面"的分裂状态。
  • 桌面用户把浏览器窗口拉窄同样切换移动布局——响应式网站的常规预期行为。
  • 所有移动选择器带 .mobile-mode 前缀，桌面样式在结构上不可能被误伤（≥700px 时类不存在）。
  • 与 isNativeMobile() 解耦：后者继续专用于引擎 isMobile 标志与原生桥行为，不承担布局职责。
阈值 700px：主流手机竖屏 CSS 宽度 360–480px，横屏 640–430px 不等；700 在"手机全量覆盖"与"平板/小窗保持桌面"之间取平衡，且避开现有 950px 断点的作用域（950px 断点行为保留不动）。

4书库页改造（一期主体）

区域桌面现状mobile-mode 行为
Header 顶部一排小图标：搜索、排序、设置、反馈报告、演示书下载、导入按钮（950px 断点已移左下） 仅保留搜索 + 排序 + 设置；触控目标 ≥44px（含 padding）；"反馈报告""演示书下载"等桌面专属入口隐藏；导入按钮维持左下固定定位（沿用现断点行为）
Sidebar 左侧常驻书架/笔记导航 默认收起（复用现有 isCollapsed 机制）；顶栏汉堡按钮滑出，滑出时全屏半透明遮罩，点遮罩或选中项后收回

Footer底部信息栏隐藏

样式落点：新增 src/assets/styles/mobile.css 集中承载全部 .mobile-mode 规则（便于整体审查与后续演进），在 App.tsx 顶部 import（与挂类逻辑同文件，便于整体回溯）；既有组件 CSS 不散改（header.css 现有 950px 断点保持原样）。

5对话框改造（一期）

  • 项目对话框全部走 vex（vex.dialog.open / vex.open 共 26 处调用）——因此只需一份覆盖规则：.mobile-mode .vex-content { width: calc(100vw - 24px); max-height: 90vh; overflow-y: auto; } 加圆角/内边距微调，即可覆盖全部现有与未来对话框。
  • DetailDialog（书籍详情）移动全屏化：触屏路径上最核心的对话框（点封面即弹），独立规则做到近全屏 + 底部操作区。
  • vex 遮罩行为保持现状不动：index.html 已全局设置 overlayClosesOnClick = false，关闭靠对话框自身按钮，移动端同样成立，不定制。

6WebView 侧配合（Kotlin，1 处）

MainActivity WebView 设置区（现 154–164 行）追加：

settings.textZoom = 100  // 屏蔽系统字体缩放，防止布局比例被打碎

Android 系统字体缩放会同步放大 WebView 的 textZoom，窄屏下直接挤碎分栏与网格；阅读字号由应用内设置（fontSize）控制，锁定 textZoom 是阅读类 App 的常规做法。

8交付物与分期

一期（本规格范围）

  • 新增 src/assets/styles/mobile.css —— 移动样式主体
  • 新增/修改门控 util（isMobileViewport）+ App.tsx 挂类 useEffect
  • MainActivity.kt：+1 行 textZoom = 100
  • header / sidebar / bookList 既有 CSS 少量配合（如触控目标内边距，如必要）
  • i18n：仅汉堡按钮 aria-label 一处新 key（en.json + zh.json）
  • Jest：isMobileViewport 用例

二期（另行设计，不在本规格内）

  • 阅读页面板（目录/设置/TTS 面板）窄屏全屏滑入
  • safe-area 避让（viewport-fit=cover + env(safe-area-inset-*)）
  • 真机反馈驱动的迭代（底栏导航、手势细节等）

风险与缓解

风险缓解
vex 全局覆盖影响个别特殊对话框布局走查清单逐个对话框过一遍；个别例外用更具体选择器单独修正
isCollapsed 复用与现有逻辑（如 importLocal 中 clientWidth < 950 判断）相互干扰一期不动 950px 判定逻辑，抽屉仅加遮罩与动画；干扰点在实施时单测确认
锁定 textZoom 使依赖系统大字号的用户字号变小应用内 fontSize/阅读设置不受影响；书库 UI 字号固定是移动 App 惯例，真机验收确认
