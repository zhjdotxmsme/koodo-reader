2. 组件设计

2.1 core/importer（纯 JVM，零 Android 依赖）

文件职责
BookRules.kt（改）+ xml 进白名单与 MIME（application/xml）；xhtml MIME 修正为 application/xhtml+xml（对齐 JS 与既有测试）；注释更新事实源为桌面 common.ts 清单 ∪ folderBridge 协议常量
FileMd5.kt（新）流式 MD5：16KB 分块读 File，返回 32 位小写 hex（与桌面 CryptoJS MD5 同算法同表示）
EpubBook.kt（新）基于 ZipFile：读 META-INF/container.xml → OPF 路径（回退：首个 *.opf 条目）→ XmlPullParser 解析 dc:title/creator/description/publisher → 封面：<meta name="cover" content="ID"/> → manifest href（回退：manifest 中文件名含 "cover" 的首张图）；路径解析处理前导 / 与 ..
ComicCover.kt（新）CBZ（ZipFile）：白名单扩展过滤（importLocal COMIC_IMAGE_EXTS 同款 14 种）→ numeric natural sort → 首图 bytes + 类型（jpg→jpeg）；与桌面 comic 封面规则一致
ImportPipeline.kt（新）纯函数管线 process(books: List<LocalBookInput>, dedup: ExistingMd5Check, outDir: File): ImportResult：逐本 格式过滤→拷贝落盘→MD5→去重→按格式提取（EPUB/CBZ/基础）→产出 BookRecord（映射 BookEntity 全列）+ 可选 CoverData(ext, bytes)；单本失败隔离计入 failures，不中断批次

2.4 数据流

SAF(文件/目录树) ──DocumentFile──▶ ImportViewModel（IO）
  └─▶ ImportPipeline.process
        ├─ BookRules.isBookName?  ─否─▶ skipped(unsupported)
        ├─ ContentResolver 流式拷贝 → filesDir/books/<key>.<ext>
        ├─ FileMd5（16KB 分块）
        ├─ 去重：Room.getByMd5 / 批内 md5  ─命中─▶ skipped(duplicate)
        ├─ EPUB → EpubBook（元数据+封面）｜CBZ → ComicCover（首图）｜其它 → 基础字段
        └─▶ BookRecord + CoverData
  └─▶ CoverStore.save（filesDir/cover/<key>.<ext>）＋ Room upsertAll（50/批）
  └─▶ LibraryScreen（StateFlow 自动刷新）→ BookCard 显示封面

4. 边界、风险与回滚

  • 不做：PDF/MOBI/TXT 封面与深度元数据、URL/OPDS 导入、AI 标题解析、JS 侧任何改动（WebView 轨不动）、云同步。
  • R-1 非常规 EPUB（缺 container.xml / 空 OPF）：回退链（首 .opf → 无封面）保证仍可入库，封面占位。R-2 SAF 树权限个别 ROM 行为差异：文件已被拷入内部存储，读权限失效只影响“重新导入新文件”，不影响已入库书。R-3 磁盘占用：书库文件双份（SAF 源 + 内部副本）——为 P2 引擎与权限健壮性付的代价，P8 体积优化时评估。
  • 回滚：本卡全部为新增文件 + 少量既有文件增量修改；revert 该提交即回到现状，无数据迁移。
