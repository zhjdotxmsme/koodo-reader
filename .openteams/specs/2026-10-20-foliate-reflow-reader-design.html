0. 范围

第一期做

  • EPUB / MOBI / AZW / AZW3 / FB2（含 FBZ）/ TXT / MD / HTML 族 / DOCX：用 foliate-js 在可见 WebView里渲染
  • 保留 CSS 版式、真目录、KF8 HUFF/CDIC
  • Compose 顶栏、底部目录、搜索、进度 CFI、TTS 入口、选词高亮/笔记
  • TXT 按 Readest：先转成内存 EPUB 再交给 foliate

第一期不做

  • PDF：继续 NativePdfScreen + pdf.js（刚修过主线程 bootstrap）
  • CBZ / CBT / CB7：继续 ComicViewerActivity
  • CBR：继续兜底岛（UnRAR / 16KB .so）
  • 云同步、桌面插件、OPDS
  • Canvas 增强（仿生阅读 / 阅读尺 / 段落模式 / 速读）：入口先藏，不接到 foliate CSS

导入白名单 BookRules.BOOK_EXTENSIONS 不变。本规格改的是打开后怎么画，不是「能导入哪些扩展名」。

1. 为什么要换引擎

当前原生 EPUB 把 XHTML 经 HtmlFlattener 拉成文本块，再用 Canvas 分页。后果：

  • 书自带 CSS 全部丢掉，版式不像书
  • 目录依赖自写 NAV/NCX 解析（v1.0.9 才修好 fragment / 嵌套 navPoint）
  • MOBI 的 HUFF/CDIC 在 Kotlin 解析器里是硬缺口，Calibre 转出来的 AZW3 常打不开

Readest 对同一批格式走 foliate-js：EPUB 当 HTML 文档画（CSS 还在），MOBI/KF8 用它自带的 HUFF 解压，FB2/CBZ/PDF 各有 make*。Android 原生轨已经有 loopback LocalAssetServer + pdf.js WebView 的成功先例，重排版书复用这条宿主模型，渲染面从「隐藏 WebView 出位图」改成「可见 foliate-view」。

2. 格式路由

扩展名第一期落点打开方式（对齐 Readest document.ts）

ReaderSessionFactory 第一期不再为上表 Foliate 行创建 PagedDocumentSession。Canvas 会话类保留，供测试与万一回滚，阅读屏主路径不调用它们。

        ▼

3.1 资源落地

  • Vendor readest/foliate-js（MIT）到 android/app/src/main/assets/foliate/，固定 commit，LICENSE 一并放入。
  • Vendor fflate（KF8 zlib 字体 / MOBI unzlib）与 TXT 转换、MD 所需的 marked 到同一目录。
  • AssetPaths.DEFAULT_ROOTS 增加 foliate。请求 /foliate/index.html 不得再拼成 foliate/foliate/index.html（pdfengine 已踩过的坑，现有单测要加一条对称用例）。

3.2 FoliateHostBridge

镜像 PdfJsHostBridge 的线程与 ready 契约，但 WebView 铺满内容区（不是 1×1 位图）。

  • bootstrap()：webView.post { setWebViewClient; loadUrl }，等 host.onEvent('ready')，禁止在 IO 线程碰 WebView。
  • open(url, format)：JS 按 §2 分派 foliate loader；失败把 message 回 Kotlin，屏幕 Toast / 错误态。
  • goTo(cfi | href | index)、toc()、search(query)、setAppearance({bg,fg,fontSize,fontFamily})。
  • relocate 事件 → 当前 CFI + 分数，写入已有 ReaderProgressPrefs。
  • 选区：selectedRange() 返回 CFI + 摘录；高亮/笔记写入现有 NoteDao，打开时 addAnnotation 回灌。

3.3 NativeEpubScreen

判断格式：Foliate 行 → AndroidView(foliate.view) + 现成 Compose 顶栏/目录底表/搜索框/TTS；Canvas / PagedDocumentSession 不再作为这些格式的主路径。

目录 UI 沿用 v1.0.9 的 ModalBottomSheet，数据源从 session.chapterLabel 换成 bridge.toc()（foliate 的 nav / ncx / mobi toc）。

外观：ShellAppearancePrefs / 阅读设置的字号、行距、边距、主题色，经 setAppearance 注入 foliate（CSS 变量 / renderer.setStyles），不再靠 Canvas Paint。

4. 数据流

  1. 书库点书 → 已有 ShellNav.reader(bookKey) → NativeEpubScreen。
  2. 屏幕 ReaderFiles.resolveBookFile → assets.publish(file) 得到 loopback URL。
  3. 主线程创建 FoliateHostBridge，IO 上只做「等 latch / 等 JS Promise」，所有 WebView API 经 post。
  4. open(url, format) 成功 → 拉 toc、恢复 CFI（ReaderProgressPrefs.cfiOf）、回灌笔记 CFI。
  5. 用户翻页 / 滚动 → relocate → 存 CFI。点目录项 → goTo(href)。
  6. 离开屏幕 → bridge.close() + assets.release(file)。

5. 错误处理

失败点表现
AssetServer 没起来与 PDF 相同的「引擎不可用」说明页，不空白
bootstrap 超时 / 错线程明确错误文案（沿用 PDF 的 ready latch，默认 10s）
foliate open 抛错（坏 zip、DRM、空文件）Toast + 可返回书库；MOBI HUFF 不再是 Kotlin 的「不支持」硬错误
TXT 转换失败降级：当单文件 HTML（<pre> 包原文）打开，仍能读
DOCX 转 HTML 失败显示现有 openError，不静默吞掉

6. 测试

  • JVM：AssetPaths 增加 foliate 根。NativeEpubScreen 对 Foliate 行不再调用 ReaderSessionFactory.open；工厂 Canvas 实现保留给 -Preader=canvas 回滚与既有分页单测。
  • JS：scripts/test-foliate-host.js 对齐 test-pdfengine.js：最小 EPUB / 带 fragment 的 NCX EPUB / 无 HUFF 的 MOBI fixture 能 open + 非空 toc + goTo。
  • 真机：PKT110 上现有那本《前2000年的中原图景》目录显示中文标题且正文有 CSS；再导一本 HUFF AZW3，确认不再报 Kotlin unsupported。

7. 许可与体积

  • foliate-js MIT、fflate MIT、marked MIT，放入 APK assets 合法；应用本体仍是 AGPL。
  • 不引入 Readest 的 Next/Tauri 层，不复制它的云同步代码。
  • 体积：foliate-js 本体很小；不把 pdf.js 再拷一份进 foliate（PDF 继续用现成 pdfengine）。

8. 回滚

用 Gradle 开关 -Preader=canvas（默认 foliate）切回 ReaderSessionFactory Canvas 路径。开关只影响重排版书；PDF / 漫画 / CBR 不受影响。第一期合入后若真机 HUFF 或 WebView 回归，可按 tag 回退而不拆 PDF 修复。
