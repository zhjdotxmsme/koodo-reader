W5b KoodoBookCard 接口反转（读代码后的关键发现）

现有 BookCard.kt（231 行）不能直接搬进 :core:ui：BookCard/BookListRow 直接接收 BookEntity（:core:data），私有 BookCover 依赖 CoverStore（Android Context + 文件 IO）并调 t()（:app 的 i18n）。直接搬会同时破坏两条边界。所以是接口反转，不是搬运：
  • :core:ui 定义 BookCardModel(title, author, formatLabel, coverSeed, isFavorite) + KoodoBookCard(model, coverPainter: Painter?, onClick, onLongClick, menu: @Composable () -> Unit)。
  • 封面解析留在 :app（CoverStore / base64 / BitmapFactory 都是平台与数据关注点），产出 Painter 传入。这同时让 Preview 不需要数据库与文件系统。
  • 长按菜单文案由 :app 以 slot 传入（t() 在 :app）。
  • CoverPalette 的 6 个品牌色与 W1b 的 token 重复定义 → 改为从 token 取，消除第二份事实源。
  • 硬编码 RoundedCornerShape(8.dp) / (4.dp) → 改走 KoodoShapes。
  • 顺带修一个 i18n 违规：contentDescription = "Favorite" 是硬编码英文（读屏可见），应走 t()。

验收：书库网格/列表观感与行为不变（拖拽重排在网格仍可用）；无功能丢失（原菜单每一项都能在新位置找到）；LibraryLogicTest 仍绿；:core:ui 仍不依赖 :core:data（用 grep 或构建依赖检查确认）。
