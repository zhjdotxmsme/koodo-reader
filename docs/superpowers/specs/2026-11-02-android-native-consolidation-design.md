# Android 原生阅读与文件适配收口设计

> 日期：2026-11-02
> 状态：设计已确认，待书面复核
> 范围：`android/` 原生客户端、Android 构建脚本及与旧 WebView 轨有关的守卫
> 关联：`docs/android-native-migration.md`、`docs/android-pdf-poc.md`

## 1. 背景与目标

当前 Android 同时存在完整 React WebView、Compose + Foliate WebView、Compose + Canvas 三套阅读路径。格式导入、外部打开、真实渲染和测试之间并不等价，导致默认产品行为不一致、大文件重复排版、PDF 缺少文本交互，以及“测试通过但真实格式未验证”。

本次目标不是继续增加格式声明，而是交付唯一的原生发布路径：

- `NativeShellActivity` 是唯一直接面向用户的应用入口。
- 可重排书籍使用 Kotlin 文档模型和 Canvas 排版，支持分页与连续滚动。
- PDF 使用原生 PDFium，直接输出位图和带坐标的文本内容。
- CBZ/CBT/CB7 沿用原生漫画阅读器。
- 删除 React 阅读岛、Foliate、pdf.js 和书籍回环 HTTP 服务。
- 统一导入、格式识别、元数据、阅读位置、标注和错误处理。
- CBR 明确不支持，不生成无法阅读的书架占位记录。
- 不迁移旧 WebView 数据，也不主动删除旧数据；已有原生 Room 数据必须保留。

“原生”指书籍正文不依赖 WebView。翻译、词典等独立功能是否使用系统组件不属于本次渲染边界。

## 2. 明确兼容边界

### 2.1 支持

- EPUB 2/3 的常见可重排内容：OPF、Spine、目录树、章节跳转、常用 CSS、图片、字体、内部链接、脚注和文本标注。
- TXT/MD：自动编码识别、章节索引、分块读取、分页与滚动。
- MOBI/AZW/AZW3：复用并完善现有 `engine/mobi`，统一转换为章节模型。
- FB2、DOCX、HTML/HTM/XHTML/XML/MHTML：沿用并完善现有解析器，输出统一章节模型。
- PDF：页渲染、缩放、页码跳转、目录、搜索、密码、文本选择、高亮、笔记、裁边、双页、OCR 和文本重排。
- CBZ/CBT/CB7：现有原生图片阅读、页缓存、缩放和双页。

### 2.2 不支持或降级

- CBR：识别后在导入前返回“不支持 CBR”，不写文件、不写 Room。
- DRM 内容：明确提示，不尝试绕过。
- 固定版式 EPUB：新导入明确拒绝；已有原生记录打开时显示不支持原因。
- 浏览器级复杂 CSS、EPUB JavaScript 和交互内容：不承诺支持；可提取的正文按线性内容降级，无法可靠提取时明确失败。
- MOBI/AZW 可解码但样式不完整时降级为线性正文；无法解码时不显示空白页。
- 扫描 PDF 没有文本层时，重排和文本选择提示改用 OCR；OCR 不伪造原始文本坐标。

## 3. 目标架构

```text
NativeShellActivity
├── Library / BookDetails / Settings / Notes
├── BookImportCoordinator
│   ├── FormatDetector
│   ├── BookMetadataParser
│   ├── AtomicBookStore
│   └── Room BookDao
├── BookReader
│   ├── ChapterLoader
│   ├── PageRenderer
│   │   ├── NativeTextSession（分页 / 滚动）
│   │   ├── PdfiumEngine
│   │   └── ComicViewerModel
│   └── AnnotationStore
├── Search / Export / Backup
└── SyncTarget / SyncCoordinator（仅接口预留）
```

接口职责：

- `BookReader`：管理一本书的打开、关闭、当前位置和阅读模式，不负责文件导入。
- `ChapterLoader`：按章节或字节块提供内容，禁止为了显示一页而加载整本书。
- `PageRenderer`：根据视口和排版设置生成当前窗口；文本、PDF、漫画可以有各自实现。
- `AnnotationStore`：保存进度、高亮、笔记和书签，屏蔽文本 CFI 与 PDF 页面坐标差异。
- `BookMetadataParser`：从文件提取统一元数据，不负责 UI 或文件复制。
- `FormatDetector`：综合文件名、MIME、文件头和容器结构给出格式及置信依据。

现有 `ReaderSession` 可以逐步适配到上述边界，不要求一次性重写所有解析器。旧接口不得再要求调用方在打开时完成整书分页。

## 4. 统一导入与外部打开

### 4.1 数据流

所有来源共用 `BookImportCoordinator`：

1. 从 SAF 文件、多选目录或 VIEW/SEND 获得可读来源。
2. 查询真实显示名和大小；显示名不可用时继续使用内容嗅探，不把 URI 文档 ID 当文件名。
3. `FormatDetector` 结合扩展名、MIME 和内容识别：
   - PDF 检查文件头。
   - ZIP 容器继续区分 EPUB、DOCX、CBZ，而不是只看 `.zip` 或后缀。
   - MOBI/AZW 检查 PalmDB/MOBI 结构。
   - RAR 文件头识别为 CBR/不支持，即使 MIME 或后缀错误也不能误入漫画阅读器。
   - 文本格式结合后缀、XML/HTML 根结构和字符集检测。
4. 不支持的格式立即返回结构化错误，不复制文件。
5. 复制到应用私有目录的临时文件，复制过程中同步计算 MD5。
6. 根据 MD5 查询已有书籍：重复时删除临时文件并返回已有 `bookKey`，不覆盖用户编辑。
7. 新书进行元数据和封面解析，原子改名为最终 `<bookKey>.<canonicalExt>`，再写 Room。
8. Room 写入失败时删除本次最终文件；进程异常留下的 `.part` 和无主文件由后续启动对账清理。

复制仍是默认策略，因为现有解析器依赖稳定的随机访问文件，且阅读不能依赖 SAF 授权生命周期。已知大小先与可用空间检查；大小未知时流式复制并正确处理空间耗尽。不得为了去重额外把整本文件读入内存。

`ImportOutcome` 必须能表示新书、重复书、不支持、读取失败、空间不足和元数据降级，并携带可导航的 `bookKey`（成功或重复时）。

### 4.2 外部打开

VIEW/SEND 不再“启动异步导入后立即打开书架”。宿主等待导入结果：

- 新书或重复书：按返回的 `bookKey` 直接进入对应阅读器。
- 不支持或失败：显示原因，用户可返回，不留下空书记录。
- 多文件导入仍进入书架并展示逐文件结果。

### 4.3 格式清单一致性

支持导入的扩展名、MIME、Intent 路由、阅读器和测试从同一格式注册表派生。`fbz`、`mht`、`markdown` 等只有实际注册导入和阅读后才可出现在任一路由中。

CBR 属于“可识别的明确不支持格式”，不属于支持导入白名单。现有桌面格式 parity 守卫改为区分“桌面支持”和“Android 明确不支持”，不能靠保留假支持项通过检查。

## 5. 元数据解析与编辑

### 5.1 解析

统一元数据字段至少包括：书名、作者、简介、出版社；格式、大小、页数、MD5 为只读文件信息。

解析来源：

- EPUB：OPF metadata。
- MOBI/AZW：EXTH 和可用头部字段。
- PDF：Document Info，必要时读取 XMP。
- DOCX：`docProps/core.xml`。
- FB2：`description/title-info`。
- HTML/MHTML：`<title>` 和 `<meta>`。
- TXT/MD、漫画：文件名和已有基础信息；存在可可靠解析的元数据时才增强，不猜测作者或出版社。

单本元数据解析失败回退到文件名，不阻断正文导入。解析在后台执行，异常必须可诊断。

### 5.2 编辑

书库提供“书籍详情/编辑元数据”入口：

- 可编辑书名、作者、简介、出版社；书名不能为空。
- 格式、大小、页数、MD5 只读。
- 保存只更新 Room，不改写书籍副本，不改变 MD5。
- 删除、重命名、最近阅读和阅读进度使用同一原生书库状态。
- 重复导入不得覆盖编辑结果。
- 重启、备份和恢复后保留编辑。

沿用现有 `BookEntity` 字段及备份结构，不为此新增 Room 列。封面自动生成保留，封面手动编辑不在本次范围。

## 6. 文本解析、增量排版与阅读

### 6.1 文档与章节加载

打开书籍只解析元数据、Spine/目录和章节位置，不立即读取所有章节。

- EPUB 等容器格式按 Spine 索引按需读取 XHTML 和资源。
- TXT 使用 `TextSource` 等随机访问抽象；编码检测读取有限探针，章节索引保存可恢复的位置，禁止整本 `readBytes()`。
- MD 在对应文本块内解析，不因此加载无关章节。
- MOBI、FB2、DOCX、HTML 族通过适配器输出统一章节模型。
- 当前排版窗口只保留当前章和必要的相邻章；跳转目录、搜索命中或 CFI 时加载目标章。

### 6.2 CSS 与资源

实现常见可重排阅读所需 CSS 子集：外部/内联样式，常用选择器与级联，字号、字体、行距、边距、颜色、背景、对齐、缩进、隐藏和图片尺寸。书籍资源按所属书籍和章节路径解析，防止路径逃逸。

不支持的 CSS 规则按条忽略并记录，不让单条规则导致整章失败。由于不执行 JavaScript，脚本和交互内容不进入正文。

### 6.3 分页、滚动和位置

- 分页与滚动共享同一章节布局结果，避免两套文字测量和标注坐标。
- 字号、字体、行距、边距、栏数、主题或视口变化只使受影响布局失效，不全书重排。
- 阅读位置以原始文档的章节标识和字符偏移为基准，同时保留桌面兼容 CFI。
- 页号只在当前布局签名下有效；跨设置恢复依赖位置锚点而非绝对页码。
- UI 优先展示章节与字符进度，不为了显示全局页码强制整书分页。
- 文本转换/净化需要保留到原始文本的映射，标注不得绑定转换后的临时偏移。

### 6.4 阅读功能

- 分页、连续滚动、字号、行距、页边距、主题色和夜间模式。
- 目录树、章节跳转、退出恢复、最近阅读和进度展示。
- 多色高亮、选中文本笔记、笔记与高亮关联、书签增删和跳转。
- 文本标注锚点包含章节标识、起止字符偏移和兼容 CFI。
- 全文搜索按章或块异步建立索引，支持取消；大文本不得一次性生成整本字符串或整本结果列表。
- 笔记和高亮可导出 JSON、Markdown，沿用桌面数据语义。

## 7. 原生 PDF

### 7.1 引擎

主引擎采用 PDFium Android 绑定。实施先做一个依赖验收构建，优先评估提供 `PdfTextPage`、字符坐标和选区矩形 API 的 `io.legere:pdfiumandroid:2.0.3`，固定通过审核的版本；`io.github.oothp:pdfium-android` 的已核查 Java API 不含文本页提取，不能单独满足本规格。必须验证：

- 所需 ABI 均有产物。
- 每个 `.so` 通过现有 16 KB 对齐守卫。
- 许可证和来源可追踪。
- 支持密码、页渲染、目录、文本及坐标提取。

若绑定不能通过任一项，使用固定 PDFium 源码版本和 NDK 自行构建绑定；不得静默退回 pdf.js，也不得在缺少文本坐标时宣称完成。

系统 `PdfRenderer` 仅保留给框架封面或快照等辅助路径，不承担文本选择主链路。

### 7.2 渲染和性能

- 直接渲染 Bitmap，不再经过 PNG/Base64/JavaScript 数据桥。
- 当前页与相邻页使用有字节预算的缓存；翻页、缩放和关闭可取消旧任务。
- 缩放按当前视口需要渲染，避免无界超大位图。
- 保留页码、目录、密码、裁边、双页、搜索、OCR 和文本重排。
- 重排使用 PDF 文本块的阅读顺序；无文本层时提示 OCR，不生成虚假正文。

### 7.3 文本选择与标注

PDF 文本块带页面坐标。Compose 覆盖层处理选择手柄、复制、高亮和笔记菜单，复用现有选词功能入口。

标注以 PDF 指纹、页号、归一化页面矩形及文本引用保存，旋转和缩放后仍能恢复。笔记列表跳回对应页和选区。PDF 坐标与文本 CFI 的差异限制在 `AnnotationStore` 适配层。

## 8. 漫画

沿用现有原生 CBZ/CBT/CB7 阅读器，并纳入统一进度、最近阅读和错误处理：

- 保留自然排序、降采样、有界页缓存、缩放和双页。
- CB7 加密、BCJ2 等不支持情况显示具体原因。
- CBR 不再进入漫画阅读器或占位页。

## 9. 同步预留

定义基于备份快照的 `SyncTarget` 和 `SyncCoordinator` 边界，后续适配 WebDAV 或本地文件夹。快照覆盖书库元数据、阅读进度、高亮、笔记、书签和设置，与现有备份模型复用。

本次不实现 WebDAV 客户端、账号、后台任务、冲突合并 UI 或自动上传，不增加网络同步行为。接口不得把 Room、Android `Context` 或具体 WebDAV 类型泄漏给阅读引擎。

## 10. 旧链路删除与发布切换

只有新路径通过对应阶段验收后，才删除被替代组件：

1. 文本主链路验收后删除 Foliate 和 Canvas 回滚开关中的旧整书分页实现。
2. PDF 主链路验收后删除 pdf.js、隐藏引擎 WebView 和 Base64 渲染桥。
3. 全部正文无需回环 HTTP 后删除 `LocalAssetServer` 及书籍发布映射。
4. 原生唯一入口验收后删除 React 岛、`MainActivity` 旧宿主、`NativeEventDispatcher` 和相关 webapp 打包步骤。
5. 构建脚本、Manifest、CI、格式守卫和用户文档同步为唯一原生路径。

发布构建不再存在 `webview/native` 或 `foliate/canvas` 产品行为开关。开发期临时测试开关不能进入最终发布形态。

## 11. 错误处理与数据安全

- 每类失败有用户可理解的格式、读取、空间、密码、DRM 或不支持提示。
- 单本失败不阻断批量导入；批处理结果能查看逐文件原因。
- 不用空白页、空目录或第 0 页跳转伪装成功。
- 导入、删除、元数据编辑和备份不修改用户原始 SAF 文件。
- 不删除旧 WebView 数据；不迁移它，新版也不会把旧数据冒充为已迁移。
- 解析不可信压缩包时继续执行路径穿越、解压大小和资源预算限制。

## 12. 测试与验收

### 12.1 自动化

- JVM：格式嗅探、真实格式解析、元数据映射、编码、章节索引、增量分页、CFI、PDF 坐标、导入去重和失败清理。
- Android instrumentation：SAF/Intent 导入、Room 持久化、Canvas 命中与滚动、PDFium 加载和文本选择、Activity 生命周期。
- 构建：唯一原生 debug/release APK、Manifest 路由、格式清单、许可证、ABI 和 16 KB 检查。
- 测试必须覆盖实际主引擎；不能用 Canvas 测试替代另一套默认引擎，也不能用“路由正确”替代正文渲染。
- 真实样本覆盖每种支持格式，另测错误后缀、无扩展名、损坏、加密、大文件、CJK、横竖屏、字体变化和进程恢复。
- Macrobenchmark 接入 CI 或明确的设备验收流程，不得默认跳过后仍宣称性能达标。

### 12.2 核心端到端场景

1. SAF 和外部 VIEW/SEND 均能导入并直接打开支持的书籍。
2. 错误后缀、无扩展名和通用 MIME 的文件进入正确阅读器。
3. CBR、DRM、固定版式 EPUB 有明确结果且无死书或空白页。
4. 重复导入返回原书并保留编辑后的元数据。
5. 元数据编辑、进度、标注和书夹在重启及备份恢复后一致。
6. 大 TXT/EPUB 可边读边加载，旋转和改字号不触发整书分页。
7. PDF 可选词、复制、多色高亮、加笔记并从笔记跳回原选区。
8. 笔记和高亮导出的 JSON/Markdown 可重新关联到原书位置。

### 12.3 性能门槛

沿用工程已有指标，在约定测试样本和设备上记录原始结果：

- 1 MB、300 章 EPUB 首帧 ≤ 1.2 秒。
- 文本翻页 P90 < 50 ms。
- 10 万字 EPUB 阅读内存峰值 < 350 MB。
- 1000 页 PDF 打开 ≤ 1.5 秒。
- 1000 本混合书籍导入不 OOM，失败和残留文件可追踪。

### 12.4 设备门槛

至少覆盖最低支持 API、常规 4 KB 页设备和 Android 15+ 16 KB 页设备。PDF 原生库逐 ABI 验证。没有真实设备或等效设备矩阵结果时，只能报告自动化完成情况，不能宣称“全面收口完成”。

## 13. 实施顺序

1. 建立真实样本与主链路测试，统一格式注册表、导入结果和元数据模型。
2. 完成原子导入、元数据编辑、外部打开直达正文和 CBR 明确拒绝。
3. 将文本会话改为章节/块增量加载，补齐分页、滚动、CSS、资源和标注。
4. 完成 PDFium 验收构建、原生渲染、文本选择、标注、缓存及现有 PDF 功能迁移。
5. 统一漫画、搜索、导出、最近阅读和备份行为，加入同步接口预留。
6. 删除旧 WebView 链路与构建开关，更新脚本、CI 和文档。
7. 跑完整自动化、真实样本和设备性能矩阵，再发布唯一原生 APK。

每个阶段保持可构建、可测试；最终删除阶段之前不得让默认构建失去已有可用阅读路径。
